# 미스터 월드 테마 투어 — 개발 계획

> 기준 문서: `미스터월드테마투어.pdf` (소프트웨어공학 71032)
> UX 레퍼런스: 여기어때 패키지(yeogi.com/package) · UI 레퍼런스: Wanderly 트래블 부킹 UI 시안
> 개발 위치: `E:\PythonProject\소공`

## 1. 목표와 범위

미스터 월드가 파는 것은 **테마별 패키지 상품**이다. 따라서 서비스 전체를 "패키지"에 집중한 구조로 만든다. 항공·숙소 단품 예약, 자유여행 같은 여기어때의 다른 축은 넣지 않는다.

| 구분 | 이번 단계(1단계, 최종 발표 대상) | 이후 단계 |
|---|---|---|
| 고객 인터페이스 | 웹 + 앱(PWA, 설치형) GUI | 음성인식(2단계), SMS 알림 실연동 |
| 직원 인터페이스 | 웹 GUI (상품·테마·창고·예약 관리) | 통계/리포트 고도화 |
| 백엔드 | FastAPI + SQLite, 실제 동작하는 API·DB | PostgreSQL 전환 |
| AI 요소 | 자연어 검색/챗 컨시어지 — **선택적 추가 기능**(핵심 흐름은 GUI만으로 완결) | 음성 → 동일 파이프라인 재사용 |

1단계에서 반드시 되어야 하는 것: 회원가입/로그인 → 테마 선택 → 상품 선택 → 스타일/옵션 변경 → 예약 → 3명 이상 시 확정 → 알림 기록, 그리고 직원이 상품/테마/물품을 등록·수정하는 것까지 **끝에서 끝까지 DB에 저장되며 동작**.

## 2. 요구사항 → 도메인 규칙 정리

### 2.1 테마 (4종, 확장 가능)

| 코드 | 테마 | 기본 제공 물품/서비스 | 차량 |
|---|---|---|---|
| `honeymoon` | 허니문 낭만 투어 | 로맨틱 스페셜 룸 데코, 커플 기념티 | 2인 전용 고급차량 |
| `parents` | 효도 힐링 투어 | 안마·지압 서비스, 건강 인삼 기념품 | 10인승 고급차량 |
| `golf` | 골프 챌린지 투어 | 골프 리조트 테마 연출, 골프 액세서리·골프공 | 10인승 고급차량 |
| `trekking` | 아웃도어 트레킹 투어 | 산악 어드벤처 연출, 아웃도어 기념품 스카프 | 10인승 고급차량 |

테마는 하드코딩하지 않고 `themes` 테이블로 관리한다. 직원이 테마를 추가/수정하면 고객 화면의 테마 탭·필터가 그대로 따라온다. 테마별 "기본 제공 물품"은 `theme_perks`로 창고 물품(`inventory_items`)과 연결한다.

### 2.2 투어 등급 스타일 (3종)

| 코드 | 스타일 | 호텔 등급 | 식사 |
|---|---|---|---|
| `classic` | 클래식 | 3성 | 도시락 |
| `grand` | 그랜드 | 4성 | 현지식 레스토랑 |
| `premium` | 프리미엄 | 5성 | 고급 레스토랑 스테이크 + 샴페인 |

- 허니문·효도 테마는 **그랜드 이상만** 선택 가능 (`themes.min_style_rank`).
- 식사에 **샴페인·커피 등 추가 옵션**을 붙일 수 있다 (`meal_addons`).
- 스타일 선택 뒤에도 **호텔 등급·교통·식사를 개별로 바꿀 수 있다**. 예: 트레킹+클래식 → 식사만 고급 레스토랑(스테이크+샴페인)으로 변경. 즉 예약에는 "스타일"이 아니라 **스타일에서 파생된 세 항목의 최종 값**이 저장된다 (`booking.hotel_grade`, `booking.transport`, `booking.meal`). 스타일은 기본값 프리셋일 뿐이다.
- 가격 = 상품 기본가 × 인원 + (스타일/개별 옵션 차액) + 추가옵션 − 단골 할인.

### 2.3 예약 확정 규칙

- 각 **출발일정(departure)** 단위로 신청 인원 합계가 **3명 이상**이면 상태가 `confirmed`로 바뀌고 출발한다.
- 확정 시 해당 출발일정에 속한 모든 예약자에게 **문자 알림**. 1단계에서는 `NotificationService`가 DB(`notifications`)와 콘솔에 기록만 하고, 실제 SMS 발송 provider는 인터페이스만 두고 나중에 교체한다.
- 상세 화면에 여기어때처럼 `예약 n명 / 잔여 m명 (최소출발 3명)`과 `출발 확정` 뱃지를 노출한다.

### 2.4 회원·고객

- 고객/직원 가입 시 **성명·주소·연락처** 저장. 역할은 `customer` / `staff`.
- **단골 할인**: 완료된 여행 횟수 기준 등급(예: 3회 이상 5%, 5회 이상 10%). 기준값은 직원 화면에서 조정 가능하게 `settings`로 둔다.
- 로그인 직후 **이전 여행 목록 팝업**: 최근 순, 각 항목에 상품명·기간·투어 등급·가격. (창을 닫으면 세션 동안 다시 안 뜸)

### 2.5 직원 기능

- 상품(패키지) 기획: 생성/수정/노출 여부, 테마 지정, 일정표(일차별), 포함/불포함, 출발일정 다건, 스타일별 가격 차액.
- 테마 관리: 추가/수정/순서/아이콘/기본 제공 물품 매핑.
- 물품 창고: 물품 등록(커플티, 인삼식품, 골프공, 스카프 …), 재고 수량, 입고/출고 이력, 예약 확정 시 자동 출고(예정 수량 차감).
- 예약 관리: 출발일정별 신청 현황, 수동 확정/취소, 알림 로그.
- 고객 관리: 목록, 여행 이력, 단골 등급.

- **한 개의 Next.js 프로젝트**에서 고객 웹·고객 앱(PWA)·직원 웹을 모두 제공한다. 고객 화면은 모바일 퍼스트 반응형, 직원 화면은 데스크톱 기준. `/staff/*`는 `staff` 역할 토큰이 있어야 진입.
- 앱 = **PWA**. `manifest.json` + 서비스워커로 홈화면 설치, 스탠드얼론 실행, 오프라인 셸. 시안의 모바일 4컷(홈/목록/상세/예약 요약)이 그대로 앱 화면이 된다.
- 인증: 이메일+비밀번호, JWT(access 30분/refresh 7일), 비밀번호는 bcrypt.
- DB: SQLite(`backend/data/app.db`) + SQLAlchemy 2.x + Alembic. `DATABASE_URL`만 바꾸면 PostgreSQL로 넘어가도록 SQLite 전용 기능(JSON1 등)은 쓰지 않는다.
- 이미지: 1단계는 `frontend/public/images/`의 정적 파일 + `packages.image_urls`(문자열 배열). 업로드는 직원 화면에서 로컬 저장(`backend/media/`)으로 처리.

## 5. API 설계 (REST, `/api/v1`)

### 공통·인증
```
POST /auth/signup            {email, password, name, phone, address, role?}
POST /auth/login             → {access_token, refresh_token}
POST /auth/refresh
GET  /me                     프로필 + loyalty
GET  /me/trips               이전 여행 목록(최근순) — 로그인 팝업용
GET  /me/bookings
```

### 고객
```
GET  /themes                               활성 테마(정렬순)
GET  /themes/{slug}
GET  /packages?theme=&style=&from=&to=&travelers=&min_price=&max_price=&sort=&q=
GET  /packages/{id}                         상세 + 일정표 + 출발일정 + 스타일 가격
GET  /packages/{id}/departures
GET  /packages/{id}/availability?departure=  예약 n명/잔여/최소출발
POST /bookings/quote                        {package_id, departure_id, style, hotel_grade?, transport?, meal?, addons[], travelers} → 가격 내역 (예약 전 실시간 계산)
POST /bookings                              생성 (status=pending)
POST /bookings/{id}/pay                     결제 시뮬레이션 → paid, 확정 조건 검사
POST /bookings/{id}/cancel

```

### 직원 (`/staff/*`, role=staff)
```
GET/POST/PUT/DELETE  /staff/themes
GET/POST/PUT/DELETE  /staff/packages           (+ itinerary, style_prices, departures 하위 리소스)
POST                 /staff/packages/{id}/publish
GET/POST/PUT         /staff/departures/{id}     status 수동 변경
GET/POST/PUT         /staff/inventory/items
POST                 /staff/inventory/items/{id}/moves   입고/출고/조정
GET                  /staff/bookings?departure=&status=
GET                  /staff/customers, /staff/customers/{id}
GET                  /staff/notifications
GET/PUT              /staff/settings
GET                  /staff/dashboard           오늘 신청, 확정 임박 일정, 재고 부족 등
```

### AI (선택 기능)
```
POST /ai/parse      {text} → {theme?, region?, date_range?, travelers?, style?, budget?}   // 자연어 → 필터
POST /ai/chat       {messages[]} → 답변 + 추천 패키지 id[]                                // 챗 컨시어지
```
`/ai/parse`는 2단계 음성인식이 붙을 때 **음성 전사 텍스트를 그대로 넣는 입구**가 된다. LLM 키가 없으면 규칙 기반 파서(키워드 사전)로 동작하도록 fallback을 둔다.

## 6. 고객 인터페이스 화면 설계

UX 원칙은 여기어때 패키지 페이지에서 가져오고, 비주얼은 Wanderly 시안(파란 프라이머리, 흰 카드, 큰 라운드, 사진 중심)을 따른다. 항목은 **패키지 하나에만** 집중하므로 여기어때 상단의 "국내숙소/해외숙소/항공/해외투어/패키지" 카테고리 아이콘 줄은 **테마 4종 아이콘 줄**로 치환한다.

### 6.1 홈 `/`
1. 헤더: 로고, (데스크톱) 테마·이벤트·마이페이지 링크, 로그인 버튼.
2. 히어로: 슬로건 "특별한 날, 가장 멋있는 장소에서 …", 배경 사진.
3. **테마 아이콘 줄**: 허니문 / 효도 / 골프 / 트레킹 (여기어때 상단 아이콘 탭과 같은 역할, 선택 시 파란 테두리 활성).
4. **검색 카드**(여기어때 검색박스 형태를 한 카드 안에): `테마·지역·명소` 입력, `출발일` 선택, `총 인원`, 파란 `검색` 버튼. 입력창 오른쪽 끝에 **마이크 아이콘 슬롯**(2단계용, 1단계는 "음성 검색 준비 중" 툴팁).
5. 이벤트 배너 캐러셀 (도트 인디케이터).
6. "테마별 맞춤 여행" 섹션: 테마 4장 카드(사진+이름+한줄 설명+`from 가격`).
7. "지금 인기 패키지" 섹션: 칩 탭(전체/허니문/효도/골프/트레킹) + 카드 리스트.
8. "출발 확정 임박" 섹션: 잔여 인원 적은 출발일정.
9. 하단 배너: 앱 설치(PWA 설치 프롬프트 트리거) — 시안의 "Unlock Exclusive Deals" 밴드 자리.
10. FAQ 아코디언, 인기 검색 키워드 칩, 푸터.

### 6.2 테마별 목록 `/themes/[slug]`
- 테마 히어로(이름·슬로건·제공 혜택 3개 아이콘).
- 상단 sticky 필터 바: 스타일(클래식/그랜드/프리미엄 — 허니문·효도는 클래식 비활성 처리 + 안내 문구), 기간, 가격대, 출발월, 정렬(추천/가격낮은/가격높은/출발임박).
- 카드(여기어때 리스트 카드 구조): 사진 · `n박 m일` · `지역` · 제목 · 뱃지(`출발 확정`, `잔여 2명`) · `성인 1인 1,299,000원~` · `그랜드 스타일 기준`.
- 무한 스크롤 or 더보기.

### 6.3 상품 상세 `/packages/[id]`
- 사진 갤러리(1/8 카운터), 뱃지(`출발 확정` / `모집 중`), 상품번호.
- 제목, 테마 태그, `예약 4명 / 잔여 6명 (최소출발 3명)`.
- 출발일 선택 칩(가로 스크롤, 잔여 인원 표시) + `출발일 변경`.
- 요약 태그 줄: `3박 4일` `4성급` `10인승 차량` `현지식`.
- **sticky 섹션 탭**: 개요 · 스타일 선택 · 포함/불포함 · 일정표 · 유의사항 (여기어때 상세와 동일한 탭 구성).
- 스타일 선택 섹션: 3개 카드(호텔 등급·식사 표기, 가격 차액), 아래에 "세부 변경" 아코디언(호텔 등급 / 교통 / 식사 / 식사 추가옵션 샴페인·커피). 변경 즉시 `/bookings/quote` 호출로 가격 갱신.
- 일정표: 일차 탭 → 방문지·식사(조/중/석)·숙소.
- **하단 고정 예약 바**: `총 2,840,000원` + `예약하기`. 모바일에서는 시안의 "Continue to Payment"와 같은 위치.

### 6.4 예약 플로우 `/booking/[packageId]`
스텝 인디케이터 4단계, 각 스텝은 한 화면.
1. 출발일·인원 확인
2. 스타일·옵션 확인/변경 (상세에서 고른 값 이월)
3. 여행자 정보 (대표자 자동 채움, 인원 수만큼 폼)
4. 결제(시뮬레이션) — 가격 요약(기본가/옵션/할인/합계), 단골 할인 적용 표시, 약관 체크 → `결제하기`
완료 화면: 예약번호, "3명 이상 모이면 확정되며 문자로 알려드립니다" 안내, 현재 신청 인원 진행바.

### 6.5 마이페이지 `/me`
- 프로필, 단골 등급(다음 등급까지 n회).
- 예약 탭: 예정 / 지난 여행. 카드에 상품·기간·등급·가격·상태.
- **로그인 직후 팝업**: "지난 여행" 모달, 최근순 리스트, `닫기` / `전체 보기`.

### 6.6 인증
- 회원가입: 이름, 이메일, 비밀번호, 연락처, 주소(우편번호 검색은 2단계, 1단계는 텍스트), 약관.
- 로그인, 비밀번호 표시 토글.

### 6.7 음성인식 대비 UX 요소 (1단계에서 자리만 마련)
2단계에서 기능만 켜면 되도록 다음을 미리 넣는다.
- 검색 카드와 모바일 하단 바에 **마이크 버튼**(`VoiceButton` 컴포넌트). 1단계: 눌러도 "음성 검색은 곧 제공됩니다" 토스트만. 컴포넌트 내부에 `onTranscript(text)` 콜백만 열어 두고, 2단계에서 Web Speech API/Whisper를 붙이면 `/ai/parse` → 검색으로 연결.
- **"이렇게 말해보세요" 힌트 칩**: "부모님이랑 10월에 편하게", "둘이서 로맨틱하게 5일", "골프 치러 4명". 클릭하면 자연어 검색(`/ai/parse`)이 동작 → 음성이 붙었을 때와 동일한 결과 흐름이라 2단계 데모가 쉬워진다.
- 상태 UI: 듣는 중(파형 애니메이션) / 인식 결과 확인 시트("허니문, 5월, 2명으로 검색할까요?" `네` `다시`) / 오류. 1단계에서는 컴포넌트와 스토리만 만들어 두고 노출하지 않음.
- 모든 주요 버튼·입력에 `aria-label`과 명확한 텍스트 라벨을 붙여 음성 명령("예약하기 눌러") 매핑이 가능하도록 함.

## 10. 구현 순서 (일정·역할 없음, 순서만)

1. **스캐폴딩**: backend/frontend 뼈대, 설정, DB 연결, 디자인 토큰, 라우팅 골격, 실행 스크립트.
2. **도메인 모델 + 시드**: 전 테이블 마이그레이션, 테마 4종·스타일 3종·샘플 패키지 8~12개·출발일정·물품 시드 데이터.
3. **인증**: 가입/로그인/refresh, role 가드, 프론트 auth 상태.
4. **고객 조회 흐름**: 홈 → 테마 목록 → 상세(일정표, 출발일정, 잔여 인원).
5. **가격 엔진 + 예약**: quote 계산(스타일/개별 옵션/추가옵션/단골 할인), 예약 4스텝, 결제 시뮬레이션, 3명 확정 로직, 알림 기록.
6. **마이페이지**: 예약 목록, 로그인 직후 이전 여행 팝업.
7. **직원 웹**: 상품·테마·출발일정 CRUD → 물품 창고 → 예약/고객/알림 → 대시보드·설정.
8. **PWA**: manifest, 서비스워커, 설치 배너, 모바일 레이아웃 마감(시안 4컷 대조).
9. **AI 선택 기능**: 규칙 기반 `/ai/parse` + 힌트 칩 → (키 있으면) LLM 파서/챗.
10. **마무리**: 시드 리셋 스크립트, pytest(가격·확정 규칙), 프론트 E2E 1개(예약 완주), README, 데모 시나리오.

## 11. 개발 환경 / 실행

- Python 3.11+, Node 20+, (선택) Docker.
- backend: `python -m venv .venv && pip install -r requirements.txt && alembic upgrade head && python -m app.db.seed && uvicorn app.main:app --reload` → http://localhost:8000/docs
- frontend: `npm i && npm run dev` → http://localhost:3000 (고객), http://localhost:3000/staff (직원)
- `.env.example` 제공: `DATABASE_URL`, `JWT_SECRET`, `SMS_PROVIDER=console`, `AI_PROVIDER=rules|openai|anthropic`, `AI_API_KEY`.
- 시드 계정: 고객 `demo@customer.com / demo1234`, 직원 `admin@mrworld.com / admin1234`.

## 12. 검증 계획

- 단위(pytest): 가격 계산(스타일 프리셋·개별 변경·추가옵션·할인), 허니문/효도 클래식 차단, 3명 확정 전이, 재고 차감.
- API: 각 라우터 happy path + 권한 거부.
- 프론트: 예약 완주 E2E(Playwright) 1본, 모바일 뷰포트 스크린샷으로 시안 대조.
- 데모 시나리오: 직원이 테마·상품·물품 등록 → 고객 3명이 같은 출발일 예약 → 확정 → 알림 로그 확인 → 고객 재로그인 시 팝업.
